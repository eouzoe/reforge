# 打包過程與發佈手段

## 產物

- 殼：平台安裝包，含載入器、公鑰與最小啟動資源。
- 基底快照：引擎與首章可玩內容，隨殼首次安裝。
- 內容包：劇情、畫面、美術、語音、音效與資料；依類型與內容邊界切分。
- manifest：版本、內容包清單、檔案清單、雜湊與簽章。

manifest 以檔案為下載與校驗單位；內容包為版本與原子切換單位。

## 打包流程

1. 驗證內容 schema 與引用完整性。
2. 以 Nx affected 找出受影響的套件與內容。
3. 建置客戶端與內容包。
4. 為每個檔案計算 SHA-256。
5. 產生 manifest，並以 Ed25519 簽章。
6. 上傳內容包與 manifest 至分發點。
7. 以原子方式切換 manifest 指標。

## 簽章與完整性

- manifest 與內容包以 Ed25519 簽章；客戶端內嵌公鑰。
- 每個檔案以 SHA-256 校驗；下載完成後先驗雜湊再驗簽章。
- 私鑰只存在於本機或 CI 密鑰，不進版本控制。
- 簽章失敗、雜湊不符或中斷的下載一律丟棄，不影響現有版本。

## 發佈

- 首次安裝包由平台通路提供；增量與按需內容由自有分發點提供。
- 發佈以 manifest 指標切換為準；切換前的版本保持可用。
- 回滾以切回先前的 manifest 指標完成，不需要重新打包。
- 內容更新不經平台審核；殼與平台整合變更仍走平台流程。

## 客戶端更新

1. 取得遠端 manifest。
2. 比對本地版本與檔案雜湊。
3. 下載缺少或變更的檔案。
4. 驗證雜湊與簽章。
5. 寫入暫存目錄。
6. 原子切換至新版本。
7. 切換失敗時保留舊版本並回滾。

已下載內容可離線遊玩；更新檢查與下載需要網路。
