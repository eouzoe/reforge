# 文檔索引

《孤屿遗章》重寫工程的文檔庫。這裡是**單一事實來源**：對話裡談成什麼不算數，寫進這裡才算數。

## 文檔清單

| 檔案 | 角色 | 更新方式 |
|---|---|---|
| [`requirements.md`](requirements.md) | 需求清單 | 只增不刪；新需求給新編號；狀態就地改 |
| [`refactor-plan.md`](refactor-plan.md) | 重寫計畫（單一事實） | 就地更新；每次實質改動補「變更記錄」 |
| [`platform-taptap.md`](platform-taptap.md) | TapTap 平台事實與工具鏈 | 每輪研究追加；每條附來源與驗證等級 |

## 維護規則

1. **只增不刪**：需求與事實永不刪除，只能改狀態（`已作廢`、`已被 R-xxx 取代`）。
2. **計畫要留痕**：`refactor-plan.md` 的實質改動記在文末變更記錄（日期＋一句話）。
3. **外部主張附來源**：URL ＋ 讀取日期 ＋ 驗證等級：
   - `直讀`：直接讀過原頁面內容
   - `摘要`：只有搜尋結果摘要，尚未直讀全文
   - `待驗`：轉述或推測，需查證
4. **狀態詞彙固定**：`已確認` / `進行中` / `待決` / `待釐清` / `擱置` / `已作廢`。
5. **編號不重用**：需求 `R-xx`、決策 `D-x`、里程碑 `M-x`、風險 `K-x`、問題 `Q-x`。
6. **語言**：繁體中文；專有名詞、程式識別符、指令、檔名保留原文。

## 這份文檔怎麼長大

| 發生什麼 | 寫到哪 |
|---|---|
| 使用者提出新需求 | `requirements.md` 追加編號 |
| 做出技術決定 | `refactor-plan.md`「關鍵決策」；狀態由 `待決` 轉 `已確認` |
| 完成一輪外部研究 | `platform-taptap.md` 或新主題文檔＋來源表 |
| 里程碑有進展 | `refactor-plan.md` 里程碑狀態欄 |
| 發現新風險 | `refactor-plan.md` 風險登記 |

上游原版仍在演進，程式碼事實以作者公開倉庫的 HEAD 為準；文檔記錄時一律附日期。
